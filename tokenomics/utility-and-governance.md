# Utility & Governance

## Token Utility

The $VQ token is deeply integrated into every aspect of the VeriQ platform, creating organic demand through real usage rather than speculation alone.

### Service Payments

All platform services are priced and paid in $VQ:

| Service | Payment Flow |
|---|---|
| Quantum Audit | User pays $VQ → Audit contract → Compute providers |
| Smart Contract Test | User pays $VQ → Test contract → Simulation nodes |
| Mining Optimization | User pays $VQ → Optimizer contract → Results delivery |
| Marketplace Compute | User pays $VQ → Escrow → Provider upon verification |

### Staking Mechanisms

**Validator Staking**

- Minimum stake required to operate a verification node
- Slashing conditions for malicious or negligent behavior
- Reward distribution proportional to stake and uptime

**Delegated Staking**

- Token holders can delegate to trusted validators
- Rewards are shared between validator and delegators
- No minimum delegation amount

### Burn Mechanism

- 10% of all platform fees are permanently burned
- Reduces circulating supply over time
- Creates deflationary pressure aligned with platform usage growth

## Governance Framework

### Proposal System

Any $VQ holder meeting the minimum threshold can submit governance proposals:

1. **Draft** — Proposal is submitted on-chain with a description and implementation plan
2. **Discussion** — Community reviews and debates the proposal (7-day period)
3. **Voting** — Token-weighted voting occurs on-chain (5-day period)
4. **Execution** — Approved proposals are implemented by the core team or automatically via smart contract

### Voting Power

- 1 $VQ = 1 vote
- Staked tokens retain full voting power
- Delegated tokens vote according to the delegator's choice (not the validator's)

### Governance Scope

Token holders can vote on:

- **Fee adjustments** — Platform fee percentages and distribution
- **Protocol upgrades** — Smart contract updates and new feature deployments
- **Treasury allocation** — How treasury funds are spent
- **Parameter changes** — Staking requirements, slashing conditions, etc.
- **Partnership approvals** — Major integrations and collaborations

### Governance Safeguards

- **Timelock** — All approved changes have a 48-hour delay before execution
- **Quorum** — Minimum participation threshold required for valid votes
- **Veto** — Emergency multisig veto for critical security issues (to be phased out as governance matures)
